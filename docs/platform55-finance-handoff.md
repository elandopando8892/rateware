# Platform 55 Sprint 7 — Finance handoff

The Rateware Finance view can prepare a local JSON handoff for MARKSMAN ERP from selected approved Rateware rows.

This handoff is deliberately observation-only. It never calls MARKSMAN, creates an invoice, creates a payment, records an accounting entry, changes a Rateware rate, or uses carrier banking details. `manual_entry_required` remains true and all financial approval flags remain false.

Each rate requires a Rateware row reference, source-upload reference, vendor reference and name, origin, destination, a canonical commercial model, a supported MARKSMAN handoff currency (`USD`, `MXN`, or `CAD`), and a positive all-in rate. Legacy commercial aliases are normalized to `fee_plus`, `cost_plus`, `sell_share`, or `brokerage`. Optional carrier-cost, customer-board, quote-date, and validity fields may be absent; when present, amounts must be positive canonical decimals, dates must be real `YYYY-MM-DD` calendar dates, and validity cannot precede the quote date. Incomplete, invalid, or noncanonical rows remain in the downloaded artifact with `status: "blocked"` and explicit `missing_fields`; no values are invented.

The artifact requires the canonical `raw_upload_id`, approved status, and linked vendor record. The upload reference preserves source lineage; resolving the source filename remains part of the controlled manual MARKSMAN workflow in this local v1. The current selected-row API does not expose `valid_through`, so the UI enables `requireValidityVerification`: an unavailable validity value produces `valid_through:verification_required` and keeps the artifact blocked instead of silently treating the rate as current. A negative observed spread also blocks handoff for human review; neither condition is corrected silently. If a selected row is no longer available on the approved surface when it is re-read, it remains in the artifact as blocked. MARKSMAN ERP remains the accounting system of record and human approval remains mandatory.
